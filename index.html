  • 성능 기준선과 출시 준비 — 알파 환경 저부하 조건에서 종단 지연 기준선을 측정. 기획 문서와 구현을 전수 대조해 출시 범위 논의 근거를 정리하고, 사내 아키텍처 리뷰 문서를 작성·발표

Cloud Functions 과금 체계 전환 및 GA 전환 준비

2026.01 ~ 현재

서버리스 상품의 과금 근거를 트레이스 기반으로 바꾸고 과금 정합성 결함을 바로잡았습니다. 정기 릴리스 계획·배포와 베타 → GA 전환 준비를 맡고 있습니다.

  • 트레이스 기반 과금 전환 — 과금 근거를 Prometheus 지표에서 OpenTelemetry 트레이스(ClickHouse)로 바꿔 운영 배포. 다중 라우터 환경에서도 중복 없이 집계되는 구조로 전환하고 운영 정합성 검증 수행
  • 운영 수집 스택 구축 — ClickHouse·OpenTelemetry Collector 용량을 산정하고, 전환 중 사용량이 0으로 집계되지 않도록 단계별 전환 순서를 설계. 수집 유실 실험으로 재시도 설정 문제를 찾아 4개 환경에 반영
  • 과금 정합성 검증 — 호출 경로·월 경계·서비스 비활성화 등 경계 조건별 사용량 집계를 점검·보완하고, 라우터 트레이스 → ClickHouse → 집계 배치까지 값이 일치함을 종단 검증
  • ClickHouse 안정화 — 메모리 한도 초과·INSERT 실패의 원인을 사용하지 않는 내부 테이블의 백그라운드 머지로 찾아 해소. 메모리 1.08GiB → 0.58GiB, 실패 0, 과금 데이터 유실 0
  • 정기 릴리스 주관 — 런타임·Go 버전 최신화, 릴리스 노트·사용자 가이드 작성, 과금 집계 경계를 피한 배포 순서 설계, 베타 → GA 전환 신청
